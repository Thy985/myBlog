# 前端项目开发指南

## 1. 开发环境搭建

### 1.1 环境要求
- **Node.js**：v16.0.0 或更高版本
- **npm**：v7.0.0 或更高版本
- **Git**：v2.0.0 或更高版本

### 1.2 安装依赖

```bash
# 克隆仓库
git clone <仓库地址>

# 进入项目目录
cd front/vue3

# 安装依赖
npm install
```

### 1.3 启动开发服务器

```bash
# 启动开发服务器
npm run dev

# 构建生产版本
npm run build

# 预览生产构建
npm run preview

# 运行测试
npm run test

# 运行测试并生成覆盖率报告
npm run test:coverage
```

## 2. 代码规范

### 2.1 命名规范

#### 2.1.1 文件命名
- **组件文件**：使用 PascalCase 命名，如 `ArticleCard.vue`
- **工具文件**：使用 camelCase 命名，如 `api.js`
- **常量文件**：使用 UPPER_CASE 命名，如 `API_URL.js`

#### 2.1.2 变量命名
- **普通变量**：使用 camelCase 命名，如 `userName`
- **常量**：使用 UPPER_CASE 命名，如 `MAX_LENGTH`
- **组件 props**：使用 camelCase 命名，如 `articleId`
- **路由参数**：使用 kebab-case 命名，如 `article-id`

#### 2.1.3 函数命名
- **普通函数**：使用 camelCase 命名，如 `getArticles()`
- **组件方法**：使用 camelCase 命名，如 `handleClick()`
- **组合式函数**：使用 `use` 前缀 + camelCase 命名，如 `useApi()`

### 2.2 代码风格

#### 2.2.1 缩进
- 使用 2 个空格进行缩进
- 不使用制表符

#### 2.2.2 换行
- 每行代码长度不超过 120 个字符
- 适当使用换行提高代码可读性

#### 2.2.3 分号
- 不使用分号
- 遵循 ESLint 规则

#### 2.2.4 引号
- 使用单引号 `'` 或反引号 `` ` ``
- 不使用双引号 `"`

### 2.3 注释规范

#### 2.3.1 单行注释
- 使用 `//` 进行单行注释
- 注释内容与 `//` 之间保留一个空格

#### 2.3.2 多行注释
- 使用 `/* */` 进行多行注释
- 适用于复杂逻辑的说明

#### 2.3.3 JSDoc 注释
- 使用 JSDoc 格式为函数和组件添加注释
- 包含参数、返回值、描述等信息

```javascript
/**
 * 获取文章列表
 * @param {Object} params - 请求参数
 * @param {number} params.current - 当前页码
 * @param {number} params.size - 每页条数
 * @returns {Promise<Object>} - 文章列表数据
 */
export async function getArticles(params) {
  // 函数实现
}
```

## 3. 组件开发规范

### 3.1 组件结构

#### 3.1.1 单文件组件 (SFC)
- 使用 Vue 3 的 Composition API
- 组件结构遵循以下顺序：
  1. `<template>` - 模板
  2. `<script setup>` - 脚本
  3. `<style scoped>` - 样式

#### 3.1.2 组件 props
- 使用 `defineProps()` 定义组件 props
- 为 props 添加类型注解和默认值
- 必要时添加 props 验证

#### 3.1.3 组件事件
- 使用 `defineEmits()` 定义组件事件
- 为事件添加类型注解
- 使用语义化的事件名称

### 3.2 组件通信

#### 3.2.1 父子组件通信
- 使用 props 传递数据
- 使用 emit 触发事件

#### 3.2.2 跨组件通信
- 使用 Pinia 进行状态管理
- 使用 provide/inject 进行依赖注入

#### 3.2.3 路由参数传递
- 使用路由参数传递数据，如 `/article/detail?id=1`
- 使用路由元信息传递配置，如 `meta: { requiresAuth: true }`

### 3.3 组件复用

#### 3.3.1 通用组件
- 放在 `components/` 目录下
- 设计为纯展示组件，通过 props 和 emit 与父组件通信

#### 3.3.2 业务组件
- 放在 `views/` 目录下
- 包含业务逻辑，可使用 composables 封装重复逻辑

## 4. API 开发规范

### 4.1 API 目录结构

```
api/
├── admin/          # 后台API
│   ├── article.js  # 文章相关API
│   ├── user.js     # 用户相关API
│   └── ...
└── frontend/       # 前台API
    ├── article.js  # 文章相关API
    ├── user.js     # 用户相关API
    └── ...
```

### 4.2 API 函数命名

- 使用语义化的函数名称
- 遵循 RESTful API 设计规范
- 示例：
  - `getArticles()` - 获取文章列表
  - `createArticle()` - 创建文章
  - `updateArticle()` - 更新文章
  - `deleteArticle()` - 删除文章

### 4.3 API 请求封装

- 使用 `composables/api.js` 中的 `request()` 函数封装 API 请求
- 统一处理错误和边界情况
- 示例：

```javascript
import { request } from '@/composables/api'
import { getArticles as getArticlesApi } from '@/api/frontend/article'

async function getArticles(params) {
  try {
    const res = await request(getArticlesApi, params, {
      showError: true,
      showSuccess: false
    })
    return res
  } catch (error) {
    console.error('获取文章列表失败:', error)
    return null
  }
}
```

## 5. 状态管理

### 5.1 Pinia Store 结构

```javascript
// stores/article.js
import { defineStore } from 'pinia'

export const useArticleStore = defineStore('article', {
  state: () => ({
    articles: [],
    loading: false,
    error: null
  }),

  getters: {
    getArticleById: (state) => (id) => {
      return state.articles.find(article => article.id === id)
    }
  },

  actions: {
    async fetchArticles() {
      this.loading = true
      try {
        // API 请求逻辑
      } catch (error) {
        this.error = error
      } finally {
        this.loading = false
      }
    }
  }
})
```

### 5.2 Store 使用规范

- **状态定义**：在 `state` 中定义初始状态
- **计算属性**：在 `getters` 中定义派生状态
- **异步操作**：在 `actions` 中处理异步逻辑
- **状态更新**：直接修改 `state` 或使用 `$patch()`

## 6. 路由管理

### 6.1 路由配置

```javascript
// router/index.js
import { createRouter, createWebHistory } from 'vue-router'

const routes = [
  {
    path: '/',
    component: () => import('@/views/frontend/index.vue'),
    meta: {
      title: '首页'
    }
  },
  // 其他路由...
]

const router = createRouter({
  history: createWebHistory(),
  routes
})

export default router
```

### 6.2 路由守卫

- **全局守卫**：处理权限验证、页面标题设置等
- **路由守卫**：处理特定路由的逻辑
- **组件守卫**：处理组件级别的逻辑

### 6.3 路由懒加载

- 使用动态导入 `() => import()` 实现路由懒加载
- 减少初始加载时间
- 示例：

```javascript
const ArticleDetail = () => import('@/views/frontend/article-detail.vue')
```

## 7. 性能优化

### 7.1 组件优化

- **组件拆分**：合理拆分组件，提高复用性
- **组件懒加载**：使用 `defineAsyncComponent()` 实现组件懒加载
- **虚拟滚动**：对长列表使用虚拟滚动

### 7.2 资源优化

- **图片优化**：使用适当的图片格式和尺寸
- **图片懒加载**：使用 `v-lazy` 指令实现图片懒加载
- **资源压缩**：配置 Vite 进行资源压缩

### 7.3 网络优化

- **API 缓存**：使用 `requestWithCache()` 实现 API 请求缓存
- **HTTP/2**：使用 HTTP/2 协议
- **CDN**：使用 CDN 加速静态资源

### 7.4 渲染优化

- **避免不必要的重渲染**：使用 `computed` 和 `watch` 优化
- **使用 `v-memo`**：对静态内容使用 `v-memo` 指令
- **使用 `v-once`**：对一次性渲染的内容使用 `v-once` 指令

## 8. 安全规范

### 8.1 XSS 防护

- **使用 `v-sanitize`**：对动态 HTML 内容使用 `v-sanitize` 指令
- **避免使用 `v-html`**：尽量避免使用 `v-html` 指令
- **输入验证**：对用户输入进行验证和过滤

### 8.2 CSRF 防护

- **添加 CSRF 令牌**：在请求头中添加 `X-CSRF-Token`
- **使用 SameSite Cookie**：配置 Cookie 的 SameSite 属性

### 8.3 认证安全

- **使用 HTTPS**：在生产环境使用 HTTPS
- **安全存储令牌**：使用 HttpOnly Cookie 存储认证令牌
- **令牌刷新**：实现令牌自动刷新机制

### 8.4 数据安全

- **敏感数据处理**：对敏感数据进行加密处理
- **避免硬编码**：避免在代码中硬编码敏感信息
- **环境变量**：使用环境变量管理配置信息

## 9. 测试规范

### 9.1 测试类型

- **单元测试**：测试单个函数或组件
- **集成测试**：测试多个组件或模块的交互
- **端到端测试**：测试完整的用户流程

### 9.2 测试文件命名

- 测试文件放在 `tests/` 目录下
- 测试文件命名为 `*.test.js` 或 `*.spec.js`

### 9.3 测试覆盖率

- 目标测试覆盖率不低于 80%
- 重点测试核心功能和业务逻辑

### 9.4 测试编写规范

- 使用 `describe()` 组织测试套件
- 使用 `it()` 或 `test()` 定义测试用例
- 使用 `expect()` 断言测试结果
- 示例：

```javascript
describe('ArticleCard 组件', () => {
  it('应该正确渲染文章标题', () => {
    const article = {
      title: '测试文章',
      content: '测试内容'
    }
    
    const wrapper = mount(ArticleCard, {
      props: { article }
    })
    
    expect(wrapper.text()).toContain('测试文章')
  })
})
```

## 10. 部署规范

### 10.1 构建配置

- **环境变量**：使用 `.env` 文件管理环境变量
- **构建命令**：使用 `npm run build` 构建生产版本
- **构建产物**：构建产物输出到 `dist` 目录

### 10.2 部署方式

- **静态部署**：部署到 Nginx、Apache 等静态文件服务器
- **容器化部署**：使用 Docker 容器化部署
- **云服务部署**：部署到 Vercel、Netlify 等云服务

### 10.3 持续集成

- **CI/CD**：配置 GitLab CI、GitHub Actions 等持续集成工具
- **自动构建**：提交代码后自动构建和部署
- **测试**：构建前运行测试，确保代码质量

## 11. 问题排查

### 11.1 常见问题

#### 11.1.1 依赖问题
- **问题**：依赖安装失败
- **解决方法**：删除 `node_modules` 和 `package-lock.json`，重新安装依赖

#### 11.1.2 构建问题
- **问题**：构建失败
- **解决方法**：检查代码语法错误，确保所有依赖都已安装

#### 11.1.3 运行时问题
- **问题**：页面空白或报错
- **解决方法**：检查浏览器控制台错误信息，定位问题所在

### 11.2 调试技巧

- **浏览器调试**：使用 Chrome DevTools 进行调试
- **Vue DevTools**：使用 Vue DevTools 调试 Vue 组件
- **日志输出**：适当使用 `console.log()` 输出调试信息
- **断点调试**：在关键位置设置断点进行调试

本开发指南旨在规范前端项目的开发流程和代码风格，提高代码质量和可维护性。开发人员应严格遵循本指南的规范，确保项目的一致性和可靠性。

随着项目的发展和技术的演进，本指南将不断更新和完善，以适应新的需求和挑战。
